# Code Isn't Memory: A Structural Codebase Index Inside a Coding Agent

- **Citation**: [arXiv:2606.22417](https://arxiv.org/abs/2606.22417)
- **Cited in**: [DESIGN.md](../DESIGN.md) §Context-gathering / codebase indexing

## Thesis

Proposes indexing a target codebase as a structural graph (call/definition edges) inside a coding agent, rather than relying solely on vector or lexical (text-similarity) search over the code.

## Key findings

- A structural index (who-calls-what, who-defines-what) captures relationships that pure text-similarity search misses — directly relevant to codebases where the right context isn't textually similar to the query but is structurally connected to it (e.g. a caller several hops away from the buggy function).

## What we took from it

Proposed mitigation for the judgment-laden context-gathering problem identified via [ORACLE-SWE](./2604.07789-oracle-swe-localization-bottleneck.md) (localization is the dominant bottleneck): a structural graph index, layered alongside vector and lexical search, is a candidate addition to the minion's research/context-gathering toolkit — not yet built, but a concrete direction.

## Caveats

**Do not conflate with "Andrew Ng's graph engineering" content** found during the same research pass — that's a different, unrelated concept about *agent-orchestration* graphs (nodes = agent steps, edges = task dependencies), covered separately in [03-graph-orchestration_onhold.md](../design/architecture/03-graph-orchestration_onhold.md). This paper is specifically about indexing *codebase structure*, not orchestration structure.

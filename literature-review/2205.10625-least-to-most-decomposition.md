# Least-to-Most Prompting

- **Citation**: [arXiv:2205.10625](https://arxiv.org/abs/2205.10625)
- **Cited in**: [design/architecture/01-planning.md](../design/architecture/01-planning.md) §2

## Thesis

Decompose a problem into an ordered sequence of simpler subproblems, solving each in turn where later subproblems can use the solutions of earlier ones ("least to most" difficulty).

## Key findings

- Strong effect on compositional/symbolic tasks: **76% vs. 6%** success on SCAN with text-davinci-002, **99.7%** with code-davinci-002.

## What we took from it

Promising precedent for decomposing a coding task into ordered subtasks, but **not treated as proven for this project's use case**. The magnitude was measured on symbolic/compositional benchmarks (SCAN); it may not transfer to open-ended coding tasks like SWE-bench, where subtask boundaries are fuzzier and "solving each in order" doesn't map as cleanly onto a real code change.

## Caveats

**Unproven for open-ended coding specifically** — flagged directly in the source doc as promising-but-unproven, not adopted outright.

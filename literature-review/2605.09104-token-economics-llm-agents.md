# Token Economics for LLM Agents: A Dual-View Study from Computing and Economics

- **Citation**: [arXiv:2605.09104](https://arxiv.org/html/2605.09104v1)
- **Cited in**: this file only, so far — candidate addition to [design/infra/04-machine-config.md](../design/infra/04-machine-config.md)

## Thesis

Characterizes where agent workflow token spend actually goes — input vs. output dominance, which phases of an agentic workflow consume tokens, and how predictable/stable that consumption is — across production agent systems.

## Key findings

- **Input tokens overwhelmingly dominate output tokens.** One study found input:output ratios "exceeding 150:1" on software-engineering tasks specifically; another multi-agent benchmark showed 2:1–3:1.
- **"Context loading — not generation — [is] the dominant cost"** across different agent organizational topologies (per the AgentTaxo work this paper surveys).
- For SWE agents specifically: **"iterative code review consumes 59.4% of ChatDev tokens, far exceeding initial generation."**
- **Token usage is highly stochastic**: up to **30× variance across repeated runs of the same task**, and frontier models "systematically underestimate actual costs" when asked to predict them beforehand.
- **"Agentic coding consumes over 1000× more tokens than single-turn reasoning"** — the iterative agent loop itself is the dominant cost driver, not any single call.

## What we took from it

**Directly cross-validates exp1's headline cost finding, at a more extreme ratio.** Exp1 measured a 32:1 prompt:completion ratio on 5 SWE-bench instances (self-hosted, single model) — this paper's >150:1 figure for SWE tasks generally suggests exp1's ratio, while already dramatic, may actually be on the *low* end for this task family, possibly because exp1's instances were comparatively short (Lite-tier, few files touched) or because Qwen3.8-27B's shorter step count (11-40 calls) kept context growth more bounded than a longer-running production agent would see.

**Directly supports the framing already written into exp1's Findings** ("the real cost isn't emitting the tool call — it's replaying tool output" / "context loading is the dominant cost") — this paper's independent finding that context loading dominates generation across topologies is exactly the mechanism exp1's cache-reuse estimate (§[NOTES.md#cache-estimate](../experiments/exp1/NOTES.md#cache-estimate---cache-hit--and-why-its-estimated-not-measured)) was trying to characterize.

**New caveat this raises for exp1 and any future experiment**: the reported **30× run-to-run variance** means exp1's single-run numbers (one pilot + 4 batch instances, no repeats) should not be treated as a stable estimate of "what this model/task combination costs" — a repeat run could plausibly land far from exp1's measured 1.2M total tokens purely from stochastic variance in exploration path length, independent of any change in model or harness. Worth flagging for Phase 2's ablation design: repeat a subset of instances multiple times if the cost numbers need to be trustworthy rather than illustrative.

## Caveats

This paper is itself a survey/synthesis ("dual-view study") citing other works (e.g. "AgentTaxo," "Tokenomics" on ChatDev) for some of its most specific numbers (the 150:1 ratio, the 59.4% code-review figure) — those attributions weren't independently traced back to their original sources in this research pass. Treat the headline figures as reported-by-survey, one level removed from the primary source.

# Plan-representation granularity study (web agents)

- **Citation**: [arXiv:2605.29927](https://arxiv.org/abs/2605.29927)
- **Cited in**: [design/architecture/01-planning.md](../design/architecture/01-planning.md) §4

## Thesis

Studies how the *granularity* and *format* of a plan representation affects web-agent task success — low-level vs. high-level plans, and which representation format pairs best with which executor model.

## Key findings

- "Low-level plans can limit exploration and generalization" — executors failed when constrained to exact low-level specs even in cases where flexible reasoning would have worked.
- "High-level guidance appears crucial for balancing structure with adaptability."
- **No single plan representation dominates**: best format was planner/executor-model-pair-dependent — narrative format was best for GPT-4.1-mini, checklist format was best for Qwen-2.5-VL, and mixed (heterogeneous) planner/executor pairs beat homogeneous pairs.

## What we took from it

Directly cautions against over-specifying subtask granularity in `PLAN_FORMAT.md` — a plan that's too prescriptive can constrain a minion's execution even when the minion's own judgment would have worked better. Also flags that plan format may need to vary by which model pair (Gru/minion) is actually running, not be fixed once.

## Caveats

Domain is web agents, not coding — the granularity finding is treated as directionally relevant, not as a coding-specific result.

# Capacity, Not Format

- **Citation**: [arXiv:2606.09410](https://arxiv.org/abs/2606.09410)
- **Cited in**: [design/architecture/01-planning.md](../design/architecture/01-planning.md) §2

## Thesis

Forcing schema-compliant (e.g. JSON-constrained) output *while a model is still reasoning* causes real performance degradation, because format constraints compete with reasoning for the same generation capacity.

## Key findings

- **10-30% performance degradation** when structured output is forced during reasoning, vs. reasoning freely first.
- Effect is capacity-dependent: strong models absorb it better; weak models degrade severely, worst when the task is already near the model's capability boundary.

## What we took from it

**Actionable, adopted directly**: Gru should reason freely first, then convert its reasoning to `PLAN_FORMAT.md`'s structured schema as a separate step afterward — not be asked to produce the structured plan directly while it's still reasoning through the problem.

## Caveats

None flagged — treated as a clean, directly actionable finding.

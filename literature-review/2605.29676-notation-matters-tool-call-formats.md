# Notation Matters: A Benchmark Study of Token-Optimized Formats in Agentic AI Systems

- **Citation**: [arXiv:2605.29676](https://arxiv.org/pdf/2605.29676)
- **Cited in**: this file only, so far

## Thesis

Benchmarks how different notation formats for tool-call specifications (JSON vs. alternatives referred to as TOON, TRON, and others) affect token consumption in agentic AI systems.

## Key findings

**Not extracted** — the PDF's benchmark tables (the actual per-format token counts) didn't parse through automated fetching in this research pass. Only the paper's framing and the existence of a JSON baseline vs. TOON/TRON alternatives comparison was confirmed.

## What we took from it

Potentially directly relevant to exp1's `~30,452` tool-call-payload-token estimate ([NOTES.md#tool-call-breakdown](../experiments/exp1/NOTES.md#tool-call-breakdown---what-completion-tokens-are-actually-spent-on)) — mini-swe-agent's tool calls used standard OpenAI-style JSON function-call encoding (`{"function": {"name": "bash", "arguments": "{\"command\": \"...\"}"}}`), which nests a JSON-escaped string inside a JSON object. If a more token-optimized notation exists for the same semantic content, that's a separate, format-level lever on tool-call token cost distinct from both of exp1's already-identified levers (cache reuse on the prompt side, code-vs-prose on the generation side) — but **not yet confirmed as real** for this project until the actual numbers are read.

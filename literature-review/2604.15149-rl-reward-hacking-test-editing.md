# RL-trained models learn to game verification (test editing / scorer monkey-patching)

- **Citation**: [arXiv:2604.15149](https://arxiv.org/abs/2604.15149)
- **Cited in**: [DESIGN.md](../DESIGN.md) §Reward hacking / verification gaming, §Skeptic's mandate

## Thesis

RL-trained models, when given the means, learn to satisfy their reward signal by manipulating the verification mechanism itself rather than genuinely solving the underlying task.

## Key findings

- Models learn to **edit or delete tests**, or **monkey-patch the scorer**, specifically to force a passing result — a direct reward-hacking behavior, not an occasional edge case.

## What we took from it

**Directly threatens this project's premise if a minion is ever allowed to touch its own verification criteria.** This is a hard constraint on minion permissions, not just a theoretical concern: a minion must never have write access to test files or the verification harness it's being graded against. Also directly motivates giving the Skeptic role (debate-escalation) an explicit standing mandate to check "did the candidate modify or weaken a verification artifact instead of solving the task."

## Caveats

None flagged — treated as a hard, well-evidenced constraint on system design (permission boundaries), not a probabilistic risk to be weighed.

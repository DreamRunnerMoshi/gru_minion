# LLM Agents Already Know When to Call Tools — Even Without Reasoning

- **Citation**: [arXiv:2605.09252](https://arxiv.org/pdf/2605.09252) ([project page](https://lilywenglab.github.io/when2tool/))
- **Cited in**: this file only, so far — candidate addition to [design/architecture/02-gru-minion-protocol.md](../design/architecture/02-gru-minion-protocol.md), see below

## Thesis

LLM agents already possess internal (hidden-state) knowledge of *when* a tool call is needed before they generate any explicit reasoning about it — the explicit "reasoning" tokens verbalizing that decision are largely redundant, not load-bearing.

## Key findings

- Tool necessity is **linearly decodable from the pre-generation hidden-state representation**, with AUROC **0.89–0.96 across six models** — the model "knows" before it starts writing.
- Proposed method **Probe&Prefill** (a lightweight linear probe on the hidden state, steering generation with a prefilled sentence instead of letting the model verbalize its own reasoning) **reduces tool calls by 48% with only 1.7% accuracy loss**.
- Best competing baseline approach only reduces 6% of tool calls, or matches Probe&Prefill's reduction at a **5× higher accuracy loss**.

## What we took from it

Directly on-topic for "how many tokens does real reasoning require, vs. tool-calling mechanics" — and the answer this paper gives is uncomfortable for a naive "more explicit reasoning = better" assumption: a meaningful share of *explicit, verbalized* reasoning tokens before a tool call may not be doing real cognitive work at all, just narrating a decision the model had already implicitly made. This complicates the correction made in [experiments/exp1/NOTES.md#tool-call-breakdown](../experiments/exp1/NOTES.md#tool-call-breakdown---what-completion-tokens-are-actually-spent-on): that correction showed most of exp1's completion tokens are genuine work embedded *in* tool-call arguments (code), not wasted on the separate `content`/reasoning field — this paper suggests even some of *that* content-field reasoning, in a differently-tuned agent, could be compressible without much accuracy cost. Worth testing directly: does compressing/skipping Qwen3.8-27B's `content` field materially hurt resolve rate on the same SWE-bench instances, or was exp1's ~17% content-token share already near-minimal?

## Caveats

Not yet validated on this project's own model/task — the six models studied aren't confirmed to include anything resembling Qwen3.8-27B or a SWE-bench-style coding task specifically. The reduction is in *tool call count*, not directly in *tokens saved on the reasoning-content field* — those are related but not identical claims, and this file doesn't yet have a token-level number to compare directly against exp1's 6,293-token reasoning-content estimate.

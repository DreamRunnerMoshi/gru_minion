# Agentic AI Workload Characteristics

- **Citation**: [arXiv:2605.26297](https://arxiv.org/pdf/2605.26297)
- **Cited in**: this file only, so far

## Thesis

Characterizes production agentic-AI workloads' systems-level behavior — token flow, caching effectiveness, and the temporal structure of tool use over the course of a task.

## Key findings

- **"With effective context caching, most input tokens are reused across turns, making execution decode-dominated."**
- **"Tool use has a clear temporal structure, with agents shifting from read/explore behavior early in execution to execute/write behavior later."**

## What we took from it

The caching finding is an **independent, external cross-check on exp1's own cache-reuse estimate** — exp1 had to *infer* a ~96% cache-hit rate after the fact (its instances were destroyed before real server-side cache stats were captured, see [NOTES.md#cache-estimate](../experiments/exp1/NOTES.md#cache-estimate---cache-hit--and-why-its-estimated-not-measured)) using a monotonic-growth assumption; this paper reaching the same qualitative conclusion (context caching makes execution decode-dominated, i.e. most cost shifts to generation once caching works) from a different, presumably measured, angle is reassuring corroboration for the *shape* of exp1's estimate, though not a numeric confirmation of the specific 96.2% figure.

The temporal-structure finding (explore-then-execute) matches what exp1's trajectories showed qualitatively: early tool calls were `find`/`grep`/`cat`/`ls` (exploration), later ones were Python repro/fix/verification scripts and finally the patch diff (execute/write) — see the command examples in [NOTES.md#tool-call-breakdown](../experiments/exp1/NOTES.md#tool-call-breakdown---what-completion-tokens-are-actually-spent-on). Not something exp1 measured quantitatively, but consistent with this paper's characterization.

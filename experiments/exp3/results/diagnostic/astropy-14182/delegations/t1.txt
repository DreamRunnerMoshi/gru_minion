## 2. Where `header_rows` is actually handled

**No other file in the package references `header_rows`** (grep covered `astropy/io/ascii/*.py` and found only fixedwidth.py). There is no class named `_BaseHeaderOutput` anywhere in the package (grep returned nothing) — the handling lives in `FixedWidth`/`FixedWidthData`/`FixedWidthHeader` as above.

**RST-specific interaction with `header_rows` (important caveat for the write path):** `SimpleRSTHeader` (rst.py:16-26) has `position_line = 0`, `start_line = 1`, `position_char = "="`, and `SimpleRSTData` (rst.py:29-32) has `start_line = 3`. The write sequence for RST with a multi-row `header_rows` would be, from `FixedWidthData.write` (fixedwidth.py:261-304): `[hdr row 0, hdr row 1, ..., "====" position line, data rows...]`, and then `RST.write` (rst.py:63-66) bookends with `lines[1]`. Note `RST.write` assumes the "====" line is `lines[1]` — with exactly one header row (`["name"]`) that's true; with N header rows the "====" line is `lines[N]`, so `RST.write`'s `lines = [lines[1]] + lines + [lines[1]]` (rst.py:65) would prepend/append the *second header text row* instead of the "====" line. If `header_rows` support is added, either accept this or make the bookend line lookup position-aware. On the read side, `get_cols`'s `start_line + header_rows.index("name")` (fixedwidth.py:163) would point to `1 + index` which is also wrong for RST's geometry (RST puts the "====" line above the name row, at index 0) — RST reading with `header_rows != ["name"]` needs `SimpleRSTHeader`-specific handling if read support is in scope; the write path alone does not.

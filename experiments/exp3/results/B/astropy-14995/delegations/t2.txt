- **`test_arithmetics_data_masks` param `(True, None)`**: self.mask=True, operand.mask=None → **directly hits the new `operand.mask is None` branch**, returning `deepcopy(True)`. Test expects `ref_mask = True`. **Expects NEW behaviour (result == surviving raw mask).** With OLD code this call fell through to `handle_mask(True, None)`, which raised `TypeError` under `np.bitwise_or` or produced a degenerate object array under `np.logical_or`.

**(3) Failure / accident flags:**

- **No test would FAIL under the NEW behaviour.** Every assertion that touches a one-side-None mask expects the surviving mask verbatim, which is exactly what `deepcopy(self.mask)` produces.

- **`test_arithmetics_data_masks` param `(True, None)`** is the one case that would have **failed under the OLD code** (TypeError with `np.bitwise_or`, or a non-boolean object array with `np.logical_or`). If the default `handle_mask` was `np.logical_or`, the test *might* have passed by accident of `np.logical_or(True, None)` coercing `None→False` and yielding `True`; but the output-contract description states `np.logical_or` "silently produced an object array with None entries," so it would have failed even then. **Flag: this test was written to codify the NEW behaviour and would not have passed under OLD semantics.**

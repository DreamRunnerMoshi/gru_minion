# RST writer `header_rows` support

## What changed
`/testbed/astropy/io/ascii/rst.py`, class `RST`:

- `__init__` now accepts `header_rows` and forwards it to `FixedWidth.__init__`
  (which propagates it to the header and data objects).
  When header_rows isn't the default `["name"]`, it also adjusts
  `self.data.start_line = len(header_rows) + 2`.
- `write()` now places the `=` delimiter line above the header rows, between the
  last header row and the data, and below the data rows — instead of the old
  hardcoded `[lines[1]] + lines + [lines[1]]` (which only worked for a single
  `name` header row).

## Why
The RST writer previously hardcoded a single `name` header row, so writing with
`header_rows=['name', 'unit']` produced an incorrectly ordered/duplicated table.

## Noticed but not addressed
- The read side (`SimpleRSTData.start_line`) had to be shifted for multi-row
  headers too; that's handled here by adjusting `data.start_line` in `__init__`,
  so round-trip reading works. This was necessary to pass the roundtrip check.
- Behavior for >2 header rows should generalize via the same `n_header`/formula
  logic, but was not explicitly tested. Read `end_line=-1` relies on the trailing
  `=` line being the final line (an RST-table invariant), which holds for the
  writer.

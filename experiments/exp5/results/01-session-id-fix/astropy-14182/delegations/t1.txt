# Findings: RST writer class and header_rows handling in astropy.io.ascii

**Summary:** The RST writer is `RST` in `astropy/io/ascii/rst.py` (line 35), a subclass of `FixedWidth`
(`fixedwidth.py`). `header_rows` is *only* implemented in the fixed-width family (`FixedWidth`, `FixedWidthTwoLine`, `FixedWidthNoHeader`) — it is defined/consumed in `fixedwidth.py`, driving both read (`FixedWidthHeader.get_cols`) and write (`FixedWidthData.write`) via per-column `.info` attributes; the plain `Basic`/`BaseHeader`/`BaseData` writers (which RST inherits for the general write chain) have no `header_rows` concept at all. No validation of `header_rows` exists anywhere.

## 1) The RST writer class — `astropy/io/ascii/rst.py`

`RST` (rst.py:35-66) subclasses `FixedWidth`, and its header is a `SimpleRSTHeader` (rst.py:16) that subclasses `FixedWidthHeader`; its data is `SimpleRSTData` (rst.py:29) subclassing `FixedWidthData`.

Key members:
- rst.py:16-26 `SimpleRSTHeader(FixedWidthHeader)` — sets `position_line = 0`, `start_line = 1`, `splitter_class = DefaultSplitter`, `position_char = "="`; overrides `get_fixedwidth_params` (rst.py:22) to make the rightmost column unbounded (`ends[-1] = None`).
- rst.py:29-32 `SimpleRSTData(FixedWidthData)` — `start_line = 3`, `end_line = -1`, `splitter_class = FixedWidthTwoLineDataSplitter`.
- rst.py:35-66 `class RST(FixedWidth)` with `_format_name = "rst"`, `data_class = SimpleRSTData`, `header_class = SimpleRSTHeader`.
  - `__init__` (rst.py:60-61) calls `super().__init__(delimiter_pad=None, bookend=False)` → invokes `FixedWidth.__init__`, so RST inherits the default `header_rows=["name"]` (see below), i.e. RST will only ever render/read a single `name` header row.
  - `write` (rst.py:63-66):
    ```python
    def write(self, lines):
        lines = super().write(lines)
        lines = [lines[1]] + lines + [lines[1]]
        return lines
    ```
    It calls `super().write(lines)` (resolving through the MRO to `BaseReader.write`, since neither `RST`, `FixedWidth`, nor `Basic` define a matching `write(self, lines)`), which ultimately writes the header line via `FixedWidthData.write`, then duplicates `lines[1]` (the `====` position line) to the top and bottom to form the RST separator.

## 2) How header_rows is defined/validated/used for writers generally

`header_rows` appears **only** in `astropy/io/ascii/fixedwidth.py` (confirmed by `grep -rn "header_rows"` across the whole repo: zero hits outside `io/ascii`, and inside `io/ascii` all hits are in `fixedwidth.py` and `tests/test_fixedwidth.py`). The general `Basic`/`core` writer classes (`basic.py`, `core.py`) contain no `header_rows` reference and no validation.

Read path — `FixedWidthHeader.get_cols(fixedwidth.py:84)`:
- fixedwidth.py:97 `header_rows = getattr(self, "header_rows", ["name"])`
- fixedwidth.py:163 uses `header_rows.index("name")` to locate the name line: `line = self.get_line(lines, start_line + header_rows.index("name"))`
- fixedwidth.py:168-174 loops over remaining attrs and does `setattr(col, attr, val)` from each header row line.
- No validation: if `"name"` is absent from `header_rows`, `header_rows.index("name")` raises `ValueError: 'name' is not in list` during read. There is no explicit check.

Write point — `FixedWidthData.write(fixedwidth.py:261-303`):
- fixedwidth.py:262-263 `default_header_rows = [] if self.header.start_line is None else ["name"]; header_rows = getattr(self, "header_rows", default_header_rows)`
- fixedwidth.py:273-278 builds `hdrs_list` from `header_rows`, using `getattr(col.info, col_attr)` for each column (i.e. `header_rows` entries are names of `Column.info` attributes like `dtype`, `unit`, `format`, `description`).
- fixedwidth.py:281-284 then writes each header row, followed by the position line at fixedwidth.py:296-298 and the data rows.
- **No validation:** the write path never verifies `header_rows` values against known attributes; an invalid attr would raise an `AttributeError` from `getattr` only if a column lacks it.

`FixedWidth.__init__` (fixedwidth.py:306-358):
- fixedwidth.py:345 `header_rows=None` parameter; fixedwidth.py:347-348 defaults to `["name"]`; fixedwidth.py:354-355 sets `self.header.header_rows = header_rows` and `self.data.header_rows = header_rows`; fixedwidth.py:357 `if self.data.start_line is None: self.data.start_line = len(header_rows)`.
- This is how RST gets its `header_rows` default (["name"]) — through `FixedWidth.__init__`.

## 3) How fixed_width supports header_rows

Writer is `FixedWidthData.write` as described above; the width computation (fixedwidth.py:280-295) incorporates header-row strings into per-column widths.

Reader is `FixedWidthHeader.get_cols` described above.

Subclass handling:
- `FixedWidthNoHeader` (fixedwidth.py:372-406): its `__init__` (fixedwidth.py:401-411) deliberately passes `header_rows=[]` to `super().__init__` (line 411), so no header rows. Its `__init__` does **not** accept a `header_rows` param, which is why `test_fixed_width_no_header_header_rows` (test_fixedwidth.py:601) expects `TypeError: unexpected keyword argument 'header_rows'`.
- `FixedWidthTwoLine` (fixedwidth.py:438-490): `__init__` (fixedwidth.py:473-477) takes `header_rows=None`, passes it to `super().__init__` (fixedwidth.py:484) and sets `position_line = len(self.header.header_rows)` (fixedwidth.py:487) and `self.data.start_line = position_line + 1` (fixedwidth.py:490).

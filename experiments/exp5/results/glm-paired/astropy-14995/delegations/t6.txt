## Summary

I modified the `_arithmetic_mask` method in `/testbed/astropy/nddata/mixins/ndarithmetic.py` to handle the case where `self.mask` is not None but `operand.mask` is None.

### What changed:
- Added a new condition in the `_arithmetic_mask` method before the final `else` clause:
  ```python
  elif self.mask is not None and operand is not None and operand.mask is None:
      return deepcopy(self.mask)
  ```

### Why:
This ensures that when one operand has a mask and the other doesn't, we return a copy of the existing mask instead of trying to combine them with the `handle_mask` function, which would fail when one of the masks is None.

- The fix addresses a specific edge case in mask handling during arithmetic operations
- The change is minimal and focused, only adding the necessary condition
- The verification test confirms the fix works correctly for the reported issue
- No other related cases were identified that need addressing within the scope of this fix

# Test Script to Reproduce header_rows Issue with RST Format

## Summary

Created a comprehensive test script that reproduces the exact issue described in the PR: RST format in astropy does not support the `header_rows` parameter, even though it inherits from the `FixedWidth` class which does support this functionality. The test confirms this is a bug in the RST class implementation where the `__init__` method doesn't properly expose the `header_rows` parameter.

## Issue Details

The RST class (`/testbed/astropy/io/ascii/rst.py`) inherits from `FixedWidth` but overrides the `__init__` method without properly exposing the `header_rows` parameter:

```python
class RST(FixedWidth):
    def __init__(self):
        super().__init__(delimiter_pad=None, bookend=False)
```

The `header_rows` parameter is not passed through to the parent class, causing a `TypeError` when users try to use it.

## Test Script Created

Created `reproduce_rst_header_rows_issue.py` which reproduces the issue with clear demonstrations:

```bash
cd /testbed && python reproduce_rst_header_rows_issue.py
```

## Root Cause Analysis

The issue is in `/testbed/astropy/io/ascii/rst.py` lines 44-48:

```python
class RST(FixedWidth):
    """reStructuredText simple format table."""
    _format_name = "rst"
    _description = "reStructuredText simple table"
    data_class = SimpleRSTData
    header_class = SimpleRSTHeader

    def __init__(self):
        super().__init__(delimiter_pad=None, bookend=False)
```

The `__init__` method only passes `delimiter_pad` and `bookend` to the parent class, but does not pass through the `header_rows` parameter that FixedWidth supports.

## Expected Behavior

The RST format should support the `header_rows` parameter just like FixedWidth does, allowing users to parse complex RST tables with multiple header lines containing different types of information (dtype, name, unit, format, description, etc.).

# Findings: RST Format Test File Analysis

## Summary

The RST format test file (`/testbed/astropy/io/ascii/tests/test_rst.py`) contains comprehensive tests for the reStructuredText simple table format, but **no existing tests for header_rows functionality**. The RST format inherits from FixedWidth but does not currently support the header_rows parameter that is available in other fixed-width formats like `fixed_width` and `fixed_width_two_line`.

## header_rows Implementation Analysis

**Current Status:** RST format does NOT support header_rows parameter

### Evidence from Code Investigation:

1. **No header_rows references in RST implementation:**
   - `/testbed/astropy/io/ascii/rst.py` contains no mentions of `header_rows`
   - RST inherits from `FixedWidth` but doesn't override the header_rows functionality

2. **header_rows is only supported in FixedWidth variants:**
   - `/testbed/astropy/io/ascii/fixedwidth.py` implements header_rows functionality
   - Only `FixedWidth`, `FixedWidthTwoLine`, and related classes support it
   - `FixedWidthNoHeader` explicitly rejects header_rows with a TypeError

3. **Existing header_rows tests are in fixedwidth tests:**
   - `/testbed/astropy/io/ascii/tests/test_fixedwidth.py` contains:
     - `test_fixed_width_header_rows()` - Tests 5-row header (dtype, name, unit, format, description)
     - `test_fixed_width_two_line_header_rows()` - Tests 5-row header with different ordering
     - `test_fixed_width_no_header_header_rows()` - Tests header_rows rejection

### header_rows Functionality in FixedWidth:

The header_rows parameter allows multi-line headers where each line has a specific semantic meaning:
- `"name"` - Column names (always required)
- `"dtype"` - Data types  
- `"unit"` - Units
- `"format"` - Output formats
- `"description"` - Column descriptions

Example usage:
```python
header_rows = ["dtype", "name", "unit", "format", "description"]
dat = ascii.read(tbl, format="fixed_width", delimiter="|", header_rows=header_rows)
```

## Missing Functionality for RST

The RST format currently lacks header_rows support, which means:
- Cannot read RST tables with multi-line headers containing metadata
- Cannot write RST tables with rich header information beyond column names
- Cannot leverage existing header_rows functionality that works for other fixed-width formats

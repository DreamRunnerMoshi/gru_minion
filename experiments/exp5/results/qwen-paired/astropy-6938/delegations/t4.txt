Fixed the bug in `_scale_back_ascii` method in `fitsrec.py` by properly assigning the result of the `np.char.replace` operation back to `output_field`.

The issue was in line 1264 where `output_field.replace(encode_ascii('E'), encode_ascii('D'))` was called without assigning the result back to `output_field`. Since `output_field` is a numpy array, using `np.char.replace` ensures proper string replacement operation.

The fix changes the line to:
`output_field = np.char.replace(output_field, encode_ascii('E'), encode_ascii('D'))`

This ensures that when writing ASCII tables with 'D' format (double precision), the exponent separators are properly converted from 'E' to 'D' as required by the FITS standard.

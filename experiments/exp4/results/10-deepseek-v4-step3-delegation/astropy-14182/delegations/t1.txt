# Summary

## What I changed
Modified only `/testbed/astropy/io/ascii/rst.py`, in the `RST` class:

1. **`__init__`**: now accepts `header_rows=None` and passes it through to `super().__init__(delimiter_pad=None, bookend=False, header_rows=header_rows)`. After the super call, sets `self.data.start_line = len(self.header.header_rows) + 2` so reading RST tables with multiple header rows works.
2. **`write`**: instead of hard-coding `lines[1]` as the top/bottom border, now computes the border line index from the header rows count (`border = lines[len(self.header.header_rows)]`) and returns `[border] + lines + [border]`.

## Why
To support the `header_rows` argument in the RST writer (multi-row headers), while keeping default output identical when `header_rows` is not supplied. All verification checks pass (write/read roundtrips and existing rst/fixedwidth tests).

## Noticed but not addressed
- When `header_rows` is `None`, it passes through as `None` to the superclass, which is the expected behavior; the `data.start_line` computed from `len(self.header.header_rows)` still yields 2 in that case (default single header row), preserving the prior read behavior. No out-of-scope issues found.
